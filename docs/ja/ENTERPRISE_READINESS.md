# 企業導入に向けた準備状況レポート（ギャップ分析）

作成日：2026-11-06　対象ブランチ：`feature/phase1-compiler-reliability`

本書は、日本のソフトウェア企業がパイロット導入を検討する際の判断材料として、**現時点で実装・検証済みのこと**と**未対応のこと**を区別して記載します。ISO 27001・SOC 2 等の認証は取得していません。

## 1. 総合評価

| 観点 | 現状 | 判定 |
|---|---|---|
| セキュリティ（コード実行の隔離） | 生成コードは Docker サンドボックス（ネットワークなし・読み取り専用・権限なし・資源制限）でのみ実行。テストで検証済み | ◎ 実装済み |
| 信頼性（品質判定） | verified は決定的な基準（静的チェック・ユニットテスト・評価ケース・非公開ホールドアウト）でのみ付与。LLM 自身は判定しない | ◎ 実装済み |
| 生成品質 | ローカルモデル（llama3.2 3B、qwen2.5-coder 7B）で生成した Skill は、実測 30 件中 verified 0 件 | ✕ 実用水準に未到達 |
| 監査ログ | 主要操作を記録、秘密情報は伏字化 | △ 保存期間・エクスポート機能なし |
| 再現性 | ベンチマークにモデルのダイジェスト・シード・コミット・サンドボックスイメージを記録 | ◎ 実装済み |
| エラーの分かりやすさ | 失敗カテゴリ・修正方法・サンドボックス未実行の理由を日本語で表示 | ○ 一部の修正ヒントは英語のまま |
| 日本語ドキュメント | 本書とクイックスタートのみ | △ 拡充が必要 |
| データの取り扱い | モデルはローカル（Ollama）で実行。入力コードは外部送信されない | ◎ 実装済み |
| 配置の管理 | ローカル単一ユーザー前提。マルチテナント・認証なし | ✕ 社内共有には未対応 |
| コストの透明性 | ローカル実行のため API 課金なし。GPU 時間は実測値を記録 | ○ |
| 保守性 | 自動テスト（バックエンド 139・フロント 7・E2E 22・SDK 6）、小さなコミット単位 | ○ |

## 2. パイロット導入前に必要な対応（優先度順）

1. **生成品質の改善**：より大きなコード生成モデル、またはタスク分割による verified 率の実証。
2. **認証・権限管理**：ユーザーアカウント、プロジェクト単位のアクセス制御、API キーのスコープ化。
3. **監査ログの運用**：保存期間、改ざん防止、CSV エクスポート。
4. **日本語化の完了**：バックエンドの修正ヒント・エラーメッセージの日本語対応。
5. **運用手順書**：バックアップ、障害時の切り分け、Docker・Ollama の監視。

## 3. 現時点でできること（デモ・評価用途）

- 日本語でエージェントを依頼し、生成・テスト・検証の様子をリアルタイムで確認する。
- 人が作成したリファレンス Skill（5 種類）を verified 状態で Claude Code・Codex に導入する（実機で確認済み）。
- 生成に失敗した場合、その理由と次の対応を確認する。

本書の数値はすべてリポジトリ内のテスト結果・ベンチマークファイルに基づきます。
